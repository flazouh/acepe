# AC-015 — ProjectionSnapshotQuery

**Wave:** Wave 1 — Projections  ·  **Size:** M  ·  **Blocked by:** AC-013, AC-014
**Blocks:** AC-018, AC-019, AC-022

## Goal

Give the UI one read path: a consistent snapshot across projections plus the sequence it was taken at.

## Files

- `packages/server/src/orchestration/Services/ProjectionSnapshotQuery.ts`
- `packages/server/src/orchestration/Layers/ProjectionSnapshotQuery.ts`

## Acceptance criteria

1. `snapshot(sessionId)` returns session, messages, turns, activities and pending approvals read inside ONE transaction.
2. The returned snapshot carries `snapshotSequence` so the client can tell whether a live event it receives is already included.
3. A snapshot taken while the pipeline is mid-apply never shows a half-applied event.
4. Query cost is bounded: no N+1 across messages.

## Notes

This is what the webview calls on session open. Getting `snapshotSequence` right is what lets the client merge live events without a refetch.
