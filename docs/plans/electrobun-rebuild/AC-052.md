# AC-052 — Make the TypeScript file index scan viable, or keep it in Rust

**Wave:** Wave 6 · **Size:** L · **Blocked by:** AC-036

## The measurement

AC-036 shipped a working file index service that fails its own performance criterion by a wide margin.

| Measurement | Result |
|---|---|
| TypeScript cold scan of this repo | **69,639 ms** for 6,921 indexed files |
| Raw `find` over the same tree | **284 ms** for 31,994 files |
| Criterion 1 allowance | within 2x of the Rust timing |

The raw walk is roughly 245x faster than the service, so the cost is in the service, not in the filesystem. Rust's own scan is fast enough that its only recorded problem was a ~5s post-import skeleton delay, which was fixed by cache pre-warming rather than by making the scan faster.

## Why this matters beyond one module

The P0 perf spike in the migration plan named `file_index` and `git` as the two ports that could invalidate the whole project, with an explicit instruction to measure them on day three rather than month nine. This is that measurement arriving late. It does not sink the rebuild, because the sidecar can host this module indefinitely, but it does mean "delete Rust" in AC-047 is not currently reachable.

## Acceptance criteria

1. Profile before optimising. Identify where the 69s goes: per-file `stat`, gitignore matching per path, Effect fiber overhead per file, or schema decoding per entry. Record the breakdown in this ticket.
2. Fix the dominant cost and re-measure with the same benchmark against this repo. Report the new number next to 69,639 ms.
3. If the scan lands within 2x of Rust, wire the service into the RPC path and mark AC-036 done.
4. If it does not, keep `file_index` in the Rust sidecar permanently, remove it from AC-047's deletion list, and record that decision in an ADR. That is an acceptable outcome; a slow file index is not.
5. ~~Run the same benchmark for AC-035's git service.~~ **Done.** `projectGitStatus` on this repo is **62 ms** median over 5 runs, against **63 ms** for `git status --porcelain` plus `git diff --numstat` from the shell. Parity with the CLI, so git stays in TypeScript. Only `file_index` is affected.

## Notes

Likely suspects, in the order worth checking:

- Gitignore matching compiled per path instead of once per directory.
- One Effect fiber per file rather than batched traversal.
- `Schema` decode per entry on the hot path.
- Sequential `stat` where a batched or concurrent read would do.

Do not weaken the benchmark to pass. The comparison is a real cold scan of this repository.

## Definition of done

- All acceptance criteria above pass, including the AC-035 measurement.
