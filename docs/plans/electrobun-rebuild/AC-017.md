# AC-017 — Record harness

**Wave:** Wave 2 — Oracle  ·  **Size:** M  ·  **Blocked by:** AC-016
**Blocks:** AC-018

## Goal

Capture real request and response traffic from the sidecar during live use, as replayable fixtures.

## Files

- `packages/harness/src/record.ts`
- `packages/harness/fixtures/`

## Acceptance criteria

1. A wrapper process sits between the app and the sidecar, forwarding traffic and writing every request, response and notification to a timestamped NDJSON fixture.
2. Fixtures record the command name, the full payload, the full response, and the ordered notifications that followed.
3. Secrets are redacted by an explicit allowlist of fields, and the redaction is tested.
4. A recorded fixture from a real Claude session with tool calls, a permission prompt, and a compaction is committed as the reference fixture.

## Notes

Record from YOUR daily use, not from synthetic scripts. The fixtures are only as good as the behaviour they capture.

## Definition of done

- All acceptance criteria above pass.
- Colocated `.test.ts` exists beside every new source file.
- `bun run typecheck` and the full test suite pass.
- `god-architecture-check` was run if this ticket touches canonical session state.
