# AC-018 — Replay harness and grader

**Wave:** Wave 2 — Oracle  ·  **Size:** L  ·  **Blocked by:** AC-017, AC-015
**Blocks:** AC-035, AC-036, AC-037, AC-038, AC-039, AC-040

## Goal

Grade any candidate TypeScript implementation against a recorded fixture in seconds. This is the ticket that makes every later ticket gradeable.

## Files

- `packages/harness/src/replay.ts`
- `packages/harness/src/grade.ts`
- `packages/harness/src/report.ts`

## Acceptance criteria

1. `bun harness replay <fixture> --against <impl>` feeds the recorded requests to a candidate implementation and diffs responses and notifications.
2. The diff is SEMANTIC, not textual: field order, generated ids and timestamps are normalised before comparison, and the normalisation rules are explicit and tested.
3. The grader exits non-zero on any unexplained difference and prints the first divergence with its path.
4. A per-fixture report shows pass, fail and skipped counts.
5. Running the harness against the Rust sidecar itself passes at 100 percent, proving the harness does not invent failures.

## Notes

That last criterion is not optional. A grader that fails against the thing it recorded is worse than no grader. This ticket is the highest-value item in the entire backlog.

## Definition of done

- All acceptance criteria above pass.
- Colocated `.test.ts` exists beside every new source file.
- `bun run typecheck` and the full test suite pass.
- `god-architecture-check` was run if this ticket touches canonical session state.
