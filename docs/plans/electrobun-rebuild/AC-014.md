# AC-014 — projection.session-messages

**Wave:** Wave 1 — Projections  ·  **Size:** M  ·  **Blocked by:** AC-012
**Blocks:** AC-015, AC-042

## Goal

Materialise the transcript: ordered messages per session with their role, content, and turn linkage.

## Files

- `packages/server/src/persistence/Services/ProjectionSessionMessages.ts`
- `packages/server/src/persistence/Layers/ProjectionSessionMessages.ts`
- `packages/server/src/persistence/Migrations/0006_projection_messages.ts`

## Acceptance criteria

1. Table `projection_session_messages` ordered by `(session_id, sequence)`, where `sequence` comes from the event log, NOT from a wall clock.
2. Transcript order is a pure function of event order. A test replays a shuffled-arrival event batch and asserts the stored order still matches sequence order.
3. Message content is stored decoded, not as an opaque provider blob.
4. Compaction seam entries are first-class rows with their own type, matching the existing seam design.

## Notes

Ordering by sequence rather than timestamp is the single change that removes Acepe's whole class of transcript-order bugs. Do not add a timestamp tiebreaker.
