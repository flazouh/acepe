# AC-051 — Bring packages/desktop under the 77-rule Effect lint

**Wave:** Wave 7 — Frontend · **Size:** L · **Blocked by:** AC-049

## Goal

`packages/desktop` had no `@effect/language-service` plugin in its tsconfig, so its `lint:effect` script reported `Checked 0 files out of 1400` and exited 0. The lint gate was passing because it checked nothing.

The plugin is now in `packages/desktop/tsconfig.json`, and the real number is **6,684 errors across 1,391 files**. Until that is burned down, desktop's `lint:effect` is report-only via `lint:effect:report` and is not chained into the root gate.

## Measured breakdown

| Rule | Count | Character |
|---|---|---|
| `strictBooleanExpressions` | 4,136 | Mechanical. 62% of the total. |
| `asyncFunction` | 851 | Real work: async/await to `Effect.gen`. |
| `globalDate` | 595 | Mechanical: `new Date()` to `DateTime`. |
| `missedPipeableOpportunity` | 278 | Style. |
| `effectSucceedWithVoid` | 229 | Mechanical. |
| `unnecessaryArrowBlock` | 219 | Mechanical. |
| `globalTimers` | 89 | Small, needs care around scheduling. |
| `newPromise` | 82 | Real work. |
| `globalErrorInEffectFailure` | 60 | Real work: typed errors. |
| `globalConsole` | 48 | Mechanical. |

## Acceptance criteria

1. Burn down by rule, not by file. Start with `strictBooleanExpressions`: it is 62% of the total and almost entirely mechanical, so one lane can clear it.
2. Each rule cleared is its own commit, with `bun run --cwd packages/desktop typecheck` and the desktop test suite green between commits.
3. `asyncFunction`, `newPromise` and `globalErrorInEffectFailure` are real conversions, not rewrites-in-place. Do them last and in smaller batches.
4. When the count reaches zero, restore `lint:effect` to the real command, delete `lint:effect:report`, and chain desktop into the root `lint:effect` and `typecheck`.
5. `bun run typecheck` and the full root test suite pass at the end.

## Notes

Do not weaken a rule to reduce the count. `scripts/check-effect-lint-strict.ts` fails the build if any of the 77 is not `"error"`, and that guard exists precisely to stop this.

The `strictBooleanExpressions` bulk is the Asana-shaped part: mechanical, file-independent, with the existing desktop suite as a free oracle.

## Definition of done

- All acceptance criteria above pass.
