# AC-053 — Decide how the shipped app gets a PTY without Node

**Wave:** Wave 8 · **Size:** M · **Blocked by:** AC-038

## The constraint

AC-038 found that **`node-pty` does not run under Bun**, and that `ChildProcess.make("node")` starts Bun rather than Node. The terminal service therefore spawns a real Node binary as a PTY host and talks JSON to `ptyHost.mjs`, discovering Node from Hermes, Homebrew, or `PATH`.

That works on this machine. It does not work as a shipping story: **Electrobun bundles Bun, not Node**, so a user without Node installed gets no terminal. Silently discovering a Homebrew path is a development convenience, not a deployment plan.

## Acceptance criteria

Pick one and implement it. Record the decision and its reasoning in an ADR.

1. **Bundle a Node runtime** with the app and point the PTY host at it. Costs bundle size; removes the dependency.
2. **Replace `node-pty`** with a PTY implementation that runs under Bun, or a native addon Bun can load. Verify against the AC-038 test suite unchanged, including the 100-cycle no-zombie test.
3. **Keep the terminal in the Rust sidecar** alongside `file_index`. Remove it from AC-047's deletion list. Costs nothing now; means two modules stay in Rust.

## Acceptance for whichever path is chosen

1. A machine with **no Node on `PATH` and no Homebrew** opens a working interactive terminal in the built app.
2. The AC-038 suite still passes, including resize, signals, login-shell PATH capture, and 100 open-and-close cycles with no leftover OS process.
3. If option 3 is chosen, AC-047 is updated and the sidecar's permanent scope is written down in one place alongside `file_index`.

## Notes

This and AC-052 are the two findings that decide whether "delete Rust" in AC-047 is reachable at all. Answer them together rather than separately.

## Definition of done

- One option implemented, an ADR recorded, and criterion 1 verified on a machine without Node.
