# AC-055 — Electrobun QA driver so live QA can run

**Wave:** Wave 8 · **Size:** L · **Blocked by:** AC-054

## Why

`packages/desktop/scripts/acepe-qa.ts` drives the **Tauri** bridge: `com.acepe.app` on ports 9223/9227, via the Tauri MCP. Against an Electrobun build it reports `bridge missing`, `webview not responsive`. There is no way to DOM-verify the rebuilt app, so **AC-050 cannot start**, and four tickets (AC-022, AC-042, AC-043, AC-045) have deferred their live criteria into it.

## The constraint that shapes the design

Electrobun's `BrowserView.executeJavascript(js)` is **fire and forget**. It calls `evaluateJavascriptWithNoCompletion` — there is no return channel. So the driver cannot simply evaluate and read a result.

The app already has what is needed to work around this: a live RPC channel between the webview and the Bun process, proven by AC-054's `acepe-shell-rpc-roundtrip`, and an HTTP server already listening on port 50000.

## Design

1. **Webview to Bun result channel.** Add a `qaResult` RPC message the webview sends to Bun, carrying `{ token, ok, value }`.
2. **Bun side eval bridge.** A `qaEval(js, token)` helper wraps the caller's JS so it reports back:
   ```js
   try { window.__acepeRpc.send.qaResult({ token, ok: true, value: (JS) }) }
   catch (e) { window.__acepeRpc.send.qaResult({ token, ok: false, value: String(e) }) }
   ```
   then calls `executeJavascript` and awaits the matching token with a timeout.
3. **HTTP surface.** Extend the existing server with `POST /qa/eval` taking `{ js }` and returning the resolved value, plus `GET /qa/health` reporting window count and current URL.
4. **CLI.** `packages/desktop/scripts/acepe-qa-electrobun.ts` with the same verb shape as the Tauri wrapper so the muscle memory transfers: `doctor`, `observe`, `inspect --selector`, `click --selector|--text`, `send --text`, `watch --text`.

## Acceptance criteria

1. `bun run qa:electrobun doctor` against a running build reports the window title and current URL, and exits non-zero when no app is running.
2. `inspect --selector=<sel>` returns real DOM facts: tag, text, attribute subset, and a match count. Not a screenshot.
3. `click --selector=<sel>` dispatches a real click and a following `inspect` observes the resulting DOM change.
4. The eval bridge times out cleanly with a named error rather than hanging when the webview does not answer.
5. The QA surface is **only present in dev and stable-unsigned builds**. A signed release build must not expose `/qa/*`. Prove it with a test on the config flag, not a comment.

## Notes

Criterion 5 matters. An HTTP endpoint that evaluates arbitrary JavaScript inside the app is a remote code execution surface. It must be compiled out of anything shipped.

Do not reach for screenshots. The repo rule is DOM verification, and this whole session has shown why: a screenshot proved the window existed but said nothing about whether the 404 was Electrobun's or SvelteKit's.

## Definition of done

- All acceptance criteria pass, and AC-050 is unblocked.
