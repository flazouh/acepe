# AC-007 — Command receipt repository

**Wave:** Wave 0 — Spine  ·  **Size:** S  ·  **Blocked by:** AC-006
**Blocks:** AC-010

## Goal

Record the outcome of every dispatched command so retries are idempotent and a previously rejected command stays rejected.

## Files

- `packages/server/src/persistence/Services/OrchestrationCommandReceipts.ts`
- `packages/server/src/persistence/Layers/OrchestrationCommandReceipts.ts`
- `packages/server/src/persistence/Migrations/0003_command_receipts.ts`

## Acceptance criteria

1. Table `orchestration_command_receipts` keyed by `command_id`, storing accepted-with-sequence or rejected-with-reason.
2. Re-dispatching an accepted `commandId` returns the original sequence and appends NO new events.
3. Re-dispatching a rejected `commandId` fails with `OrchestrationCommandPreviouslyRejectedError` and appends nothing.
4. Receipts are written in the same transaction as the events they describe.

## Notes

This is what makes the RPC boundary safe to retry, which matters because the webview can reconnect mid-turn.
