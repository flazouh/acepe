# AC-005 — SQLite client layer and migration runner

**Wave:** Wave 0 — Spine  ·  **Size:** M  ·  **Blocked by:** AC-001
**Blocks:** AC-006

## Goal

Stand up `@effect/sql-sqlite-bun` against the existing Acepe SQLite file and run forward-only migrations written as Effects.

## Files

- `packages/server/src/persistence/Layers/Sqlite.ts`
- `packages/server/src/persistence/Migrations.ts`
- `packages/server/src/persistence/Migrations/0001_init.ts`

## Acceptance criteria

1. A `SqliteLive` Layer opens the same database file the Tauri app uses today, resolved from Acepe's existing app-data path logic.
2. Migrations are numbered TypeScript modules returning `Effect`s, applied in order, recorded in a `_migrations` table.
3. The runner is idempotent: running it twice applies nothing the second time.
4. Opening the LIVE Acepe database read-only and running `SELECT` against an existing sea-orm table succeeds. This is the P0 parity spike, promoted to a test.
5. `WAL` mode and `foreign_keys=ON` are set explicitly on connect.

## Notes

sea-orm still owns the schema at this point. Do not add or alter sea-orm's tables in this ticket; only add new tables under a distinct prefix.

## Definition of done

- All acceptance criteria above pass.
- Colocated `.test.ts` exists beside every new source file.
- `bun run typecheck` and the full test suite pass.
- `god-architecture-check` was run if this ticket touches canonical session state.
