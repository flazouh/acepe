# AC-023 — ProviderRegistry and ProviderAdapterRegistry

**Wave:** Wave 4 — Providers  ·  **Size:** M  ·  **Blocked by:** AC-022
**Blocks:** AC-024, AC-025, AC-026, AC-027, AC-028, AC-029

## Goal

Define the provider seam once so every adapter ticket below is independent and parallel.

## Files

- `packages/server/src/provider/Services/ProviderRegistry.ts`
- `packages/server/src/provider/Layers/ProviderRegistry.ts`
- `packages/server/src/provider/Layers/ProviderAdapterRegistry.ts`

## Acceptance criteria

1. A `ProviderAdapter` interface: start a session, send a prompt, cancel a turn, stream normalised updates, report capabilities.
2. Adapters emit CONTRACT events, never provider-shaped payloads. Normalisation happens inside the adapter.
3. The registry resolves an adapter by provider id and reports which providers are installed and authenticated.
4. Capability resolution is data, not branching: a missing capability disables UI rather than throwing.
5. A fake adapter implementation exists for tests and needs no network.

## Notes

Every adapter ticket below depends only on THIS ticket, which is what makes Wave 4 fully parallel. Get the interface right before fanning out.

## Definition of done

- All acceptance criteria above pass.
- Colocated `.test.ts` exists beside every new source file.
- `bun run typecheck` and the full test suite pass.
- `god-architecture-check` was run if this ticket touches canonical session state.
