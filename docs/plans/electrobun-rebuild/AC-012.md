# AC-012 — ProjectionPipeline runner

**Wave:** Wave 1 — Projections  ·  **Size:** L  ·  **Blocked by:** AC-011, AC-010
**Blocks:** AC-013, AC-014, AC-030, AC-031, AC-032, AC-033, AC-034

## Goal

Run the registered projectors over the event stream, each advancing its own checkpoint.

## Files

- `packages/server/src/orchestration/Services/ProjectionPipeline.ts`
- `packages/server/src/orchestration/Layers/ProjectionPipeline.ts`

## Acceptance criteria

1. A `ProjectorDefinition` is `{name, apply(event, tx)}`. The pipeline holds a registry of them.
2. On start, each projector catches up from its checkpoint by reading the event store, then switches to the live PubSub without dropping or double-applying an event at the seam.
3. Each event is applied and checkpointed in ONE transaction per projector.
4. A projector that fails logs, marks itself degraded, and does not stall the others.
5. `rebuild(name)` truncates that projector's tables, resets its checkpoint, and replays from 0.
6. A test kills the pipeline mid-catch-up and restarts it, asserting the resulting tables are identical to an uninterrupted run.

## Notes

The catch-up-to-live handover is the classic bug in this pattern. Write that test first.
