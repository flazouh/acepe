# AC-010 — OrchestrationEngine

**Wave:** Wave 0 — Spine  ·  **Size:** L  ·  **Blocked by:** AC-007, AC-008, AC-009
**Blocks:** AC-012, AC-022

## Goal

Serialize command dispatch, persist events, advance the read model, and publish events to subscribers.

## Files

- `packages/server/src/orchestration/Services/OrchestrationEngine.ts`
- `packages/server/src/orchestration/Layers/OrchestrationEngine.ts`

## Acceptance criteria

1. Commands enter an unbounded `Queue` and are processed ONE at a time, so the read model is never read concurrently with a write.
2. Each dispatch returns a `Deferred` resolving to `{sequence}` or failing with a typed dispatch error.
3. Accepted events are appended, the in-memory read model is advanced, and events are published to a `PubSub`.
4. A command whose invariants fail writes a rejection receipt and resolves the Deferred as a failure, without touching the event store.
5. Engine shutdown drains the queue and releases the PubSub through a `Scope`.
6. Metrics: command count, dispatch duration, ack duration, tagged by command type.

## Notes

Read t3code `orchestration/Layers/OrchestrationEngine.ts` (310 lines) before writing this. The queue-plus-Deferred pattern is the whole trick and it is easy to get subtly wrong.
