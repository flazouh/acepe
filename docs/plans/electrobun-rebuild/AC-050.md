# AC-050 — Live QA of the rebuilt app

**Wave:** Wave 8 — Cutover · **Size:** L · **Blocked by:** AC-022, AC-045

## Goal

Drive the real running app and confirm the rebuild behaves correctly in the browser engine, not just in tests. Nothing in AC-001 to AC-049 exercises the app as a user does; the harness grades protocol traffic and the suites grade units.

## Prerequisite

Read `.claude/skills/acepe-dev-app-qa/SKILL.md` and follow it. It is required before visually inspecting the dev app.

## Acceptance criteria

1. **DOM-verify every claim.** Assert against the DOM through the QA tooling. A screenshot is not evidence; it is a picture of one frame.
2. Drive one full session end to end in the running app: create a project, create a session, send a message, watch tokens stream, answer a permission prompt, and see a tool call render.
3. Restart the Bun process mid-stream and confirm the transcript recovers from projections with no lost or duplicated message.
4. Verify transcript order is stable under fast streaming. Order comes from event sequence, so a shuffled arrival must not reorder the view.
5. Verify the viewport: follow-release is gated on user-intent events, and content-visibility re-measure bursts do not strand follow above the edge. Confirm with a live rAF trace, not a screenshot.
6. Run the same checks on all three webview engines that ship: WebKit on macOS, Edge WebView2 on Windows, and CEF or WebKitGTK on Linux, or record explicitly which platforms were skipped and why.

## Notes

Reuse a single session thread for the whole QA run. Spawning a session per check litters the sidebar and session delete is hover-gated, so it cannot be scripted away.

Record every defect found as its own ticket rather than fixing inline, unless the fix is a one-liner. QA that turns into an unbounded repair session stops being QA.

## Definition of done

- All acceptance criteria above pass, or the gaps are recorded as tickets.
- `bun run typecheck` and the full root test suite pass.
