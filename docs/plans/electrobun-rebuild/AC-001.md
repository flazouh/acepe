# AC-001 — Scaffold packages/contracts and pin the Effect catalog

**Wave:** Wave 0 — Spine  ·  **Size:** S  ·  **Blocked by:** yes (no blockers)
**Blocks:** AC-002, AC-005, AC-020, AC-021

## Goal

Create the contracts package that both the Bun process and the webview import, and lock every Effect package to one version through a Bun workspace catalog.

## Files

- `package.json`
- `packages/contracts/package.json`
- `packages/contracts/src/index.ts`
- `tsconfig.base.json`

## Acceptance criteria

1. Root `package.json` gains a `catalog` block pinning `effect`, `@effect/platform-bun`, `@effect/platform-node`, `@effect/sql-sqlite-bun`, `@effect/vitest`, `@effect/language-service` to the SAME exact version (no `^`, no `~`).
2. `packages/contracts` builds with `tsdown` and exports from `src/index.ts`.
3. `packages/contracts` has ZERO runtime dependencies other than `effect`. It must not import from `packages/desktop` or from any adapter.
4. `@effect/language-service` is enabled in `tsconfig.base.json` under `compilerOptions.plugins`.
5. `bun run typecheck` passes at the root.

## Notes

Copy the catalog mechanism from t3code's root `package.json`.

**Pinned versions, verified against npm on 2026-08-20. Use these exact strings, no `^`, no `~`:**

```json
"catalog": {
  "effect": "4.0.0-rc.111",
  "@effect/platform-bun": "4.0.0-rc.111",
  "@effect/platform-node": "4.0.0-rc.111",
  "@effect/sql-sqlite-bun": "4.0.0-rc.111",
  "@effect/vitest": "4.0.0-rc.111",
  "@effect/language-service": "0.87.2"
}
```

`effect@4` is at release candidate, not stable. The `rc` dist-tag resolves to `4.0.0-rc.111`; `latest` still resolves to `3.22.1`, so an unpinned install silently gives you v3. That is the reason this ticket exists before any other.

`@effect/language-service` versions independently of the ecosystem and is NOT on the shared `4.0.0-rc.111` number. Do not try to align it.

There is no `@effect/atom-svelte`. AC-021 builds that binding; do not add an atom package to the catalog.
