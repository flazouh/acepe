# AC-021 — effect-svelte bridge package

**Wave:** Wave 3 — Shell and first slice  ·  **Size:** M  ·  **Blocked by:** AC-001
**Blocks:** AC-022, AC-041, AC-044

## Goal

Build the Svelte binding that does not exist upstream, small enough that adopting an official package later is a rename.

## Files

- `packages/effect-svelte/src/atom.svelte.ts`
- `packages/effect-svelte/src/runtime.ts`
- `packages/effect-svelte/src/resource.ts`
- `packages/effect-svelte/src/scope.ts`

## Acceptance criteria

1. `atomState(atom, registry)` exposes a `.current` getter backed by `createSubscriber` from `svelte/reactivity`.
2. `runtime.runPromise` is bound to the single app `ManagedRuntime`; nothing else in the app constructs a runtime.
3. `resource(effect)` exposes loading, success and tagged-failure states as a plain object with getters.
4. `componentScope()` ties an Effect `Scope` to `onDestroy` so subscriptions are released with the component.
5. The whole package is under 250 lines and has no dependency on any Acepe module.
6. A test mounts a component, pushes three values through an atom, unmounts, and asserts the subscription was released.

Naming convention decision goes in `AGENTS.md` in this ticket: how to tell Svelte's `$effect` rune apart from an Effect value at a glance. Settle it once, here.
