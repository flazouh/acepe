# AC-011 — Projection state and per-projector checkpoints

**Wave:** Wave 1 — Projections  ·  **Size:** S  ·  **Blocked by:** AC-006
**Blocks:** AC-012

## Goal

Track how far each named projector has consumed the event log so projectors can restart, rebuild, or lag independently.

## Files

- `packages/server/src/persistence/Services/ProjectionState.ts`
- `packages/server/src/persistence/Layers/ProjectionState.ts`
- `packages/server/src/persistence/Migrations/0004_projection_state.ts`

## Acceptance criteria

1. Table `projection_state` keyed by projector name, storing the last applied sequence.
2. `checkpoint(name, sequence)` and `lastApplied(name)` are transactional.
3. Resetting a single projector to sequence 0 causes only that projector to rebuild on next run.
4. A projector name that has never run reports sequence 0 rather than failing.

## Notes

Independent checkpoints are what let you rebuild one projection without touching the others. Do not collapse this into a single global cursor.
