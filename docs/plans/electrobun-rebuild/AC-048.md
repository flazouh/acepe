# AC-048 — Factor the repeated event envelope out of the decider

**Wave:** Wave 0 — Spine · **Size:** S · **Blocked by:** AC-008

## Goal

`packages/server/src/orchestration/decider.ts` repeats the nine-field event envelope in all eleven event constructors. Every future command ticket adds another copy. Factor it into one helper before the file grows.

## Files

- `packages/server/src/orchestration/decider.ts`

## Acceptance criteria

1. A single `withEnvelope` helper builds `sequence`, `eventId`, `aggregateKind`, `aggregateId`, `occurredAt`, `commandId`, `causationEventId`, `correlationId` and `metadata`. Each event constructor spreads it and adds only `type` and `payload`.
2. The literal `causationEventId: null` appears exactly once in the file.
3. Every existing decider test still passes with no test edits. If a test needs changing, the refactor changed behaviour and is wrong.
4. `bun run --cwd packages/server typecheck` and `lint:effect` both pass.

## Notes

The AC-008 lane claimed this was impossible because "a shared helper either needs object spread or a type assertion, and both are banned here". **That claim is wrong.** Object spread is not banned by any of the 77 Effect diagnostics; only `unsafeEffectTypeAssertion` is, and that is about asserting Effect types. A spread-based helper was verified lint-clean against this exact config before this ticket was written.

t3code solves the same problem with `withEventBase` in its decider. Use the same shape.

## Definition of done

- All acceptance criteria above pass.
- `bun run --cwd packages/server test` passes with no test file modified.
