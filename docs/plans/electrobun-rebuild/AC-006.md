# AC-006 — Event store table and OrchestrationEventStore service

**Wave:** Wave 0 — Spine  ·  **Size:** M  ·  **Blocked by:** AC-004, AC-005
**Blocks:** AC-007, AC-011

## Goal

Persist the append-only event log with a global monotonic sequence.

## Files

- `packages/server/src/persistence/Services/OrchestrationEventStore.ts`
- `packages/server/src/persistence/Layers/OrchestrationEventStore.ts`
- `packages/server/src/persistence/Migrations/0002_event_store.ts`

## Acceptance criteria

1. Table `orchestration_events` with columns for every envelope field, a UNIQUE index on `event_id`, and an index on `(aggregate_kind, aggregate_id, sequence)`.
2. `append(events)` assigns sequences inside a single transaction and returns the last sequence.
3. `readFrom(sequence, limit)` returns a `Stream` of decoded events in sequence order.
4. Concurrent appends never produce a duplicate or a gap in `sequence`. Prove it with a test that appends from 50 concurrent fibers and asserts the sequences are exactly 1..N.
5. Decode failures surface as a `Schema.TaggedError`, never as a thrown exception.

## Notes

The service tag lives in `Services/`, the live implementation in `Layers/`. Keep that split for every repository from here on; it is the convention the whole backend depends on.
