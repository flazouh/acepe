# AC-026 — Cursor adapter via ACP

**Wave:** Wave 4 — Providers  ·  **Size:** M  ·  **Blocked by:** AC-023
**Blocks:** AC-046

## Goal

Replace 3,465 lines of hand-written Rust with the ACP SDK plus a registry entry.

## Files

- `packages/server/src/provider/Layers/CursorAdapter.ts`

## Acceptance criteria

1. Uses `@agentclientprotocol/sdk` pinned to v1; `experimental/v2` is not imported.
2. Launch configuration comes from the ACP registry `cursor/agent.json`, not from hand-maintained install code.
3. Graded against a recorded Cursor fixture. Any behaviour the fixture shows that ACP cannot carry is listed explicitly in the ticket comment as an accepted loss.

## Notes

This is where the ACP fidelity tradeoff becomes concrete. Record the losses; do not let them pass silently.

**Harness:** `packages/harness/fixtures` has `claude-session-reference.ndjson` and `tracer-bullet-reference.ndjson`. There is no recorded Cursor fixture. Grading against the harness is blocked. The adapter tripwire test fails if a `cursor` filename appears under that fixtures directory without a grading pass.

**Accepted losses** versus the handwritten Rust Cursor adapter (ACP v1 cannot carry these, and no Cursor fixture exists to prove them):

- Extension methods: `cursor/ask_question`, `cursor/create_plan`, `cursor/update_todos`, `cursor/task`, `cursor/generate_image` (and `_cursor/...`)
- SQLite `store.db` sparse tool-call enrichment
- Thinking-prefixed `agent_message_chunk` upgraded to thought chunks
- Web-search notification dedup (`web_search_*` / `ws_*`)
- Skills from `~/.cursor/skills`
- Model discovery via `--list-models` (not ACP)
- `cursor_login` beyond ACP `authenticate`
- History reconnect / provider-owned session snapshot
- ACP terminal methods (PTY is not wired; client does not advertise `terminal`)
