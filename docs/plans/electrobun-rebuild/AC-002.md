# AC-002 — Branded id schemas and base schemas

**Wave:** Wave 0 — Spine  ·  **Size:** S  ·  **Blocked by:** AC-001
**Blocks:** AC-003

## Goal

Define every identifier as a branded Schema so a ProjectId can never be passed where a SessionId is expected.

## Files

- `packages/contracts/src/baseSchemas.ts`
- `packages/contracts/src/ids.ts`

## Acceptance criteria

1. Branded types for `ProjectId`, `SessionId`, `TurnId`, `MessageId`, `ActivityId`, `ToolCallId`, `CheckpointId`, `ApprovalRequestId`, `EventId`, `CommandId`, `ProviderSessionId`.
2. Each id has a `make` constructor and a decoder; raw `string` is never assignable to a branded id.
3. `IsoDateTime`, `Sequence` (non-negative integer) and `JsonObject` live in `baseSchemas.ts`.
4. Unit test proves a `ProjectId` fails to typecheck as a `SessionId` (use a `// @ts-expect-error` assertion).

## Notes

Acepe's domain word is `session`, not t3code's `thread`. Keep Acepe's vocabulary in the contract; do not import their naming.

## Definition of done

- All acceptance criteria above pass.
- Colocated `.test.ts` exists beside every new source file.
- `bun run typecheck` and the full test suite pass.
- `god-architecture-check` was run if this ticket touches canonical session state.
