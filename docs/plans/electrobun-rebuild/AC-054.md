# AC-054 — The built app starts Bun but never opens a window

**Wave:** Wave 8 · **Size:** M · **Blocked by:** AC-020

## Reproduction

```bash
rm -rf packages/desktop/electrobun-build
bun run --cwd packages/desktop electrobun:build
cp -R packages/desktop/electrobun-build/stable-macos-arm64/Acepe.app /tmp/Acepe.app
/tmp/Acepe.app/Contents/MacOS/launcher
```

Observed, on a clean build of `dcb26e5c9`+:

1. The launcher self-extracts on first run (~6s decompress, ~360ms untar), then on later runs loads from flat files.
2. It spawns `./bun … Resources/main.js`, which **stays alive**.
3. Log stops at `[LAUNCHER] Loading app code from flat files`. Nothing further, on stdout or stderr.
4. **No window ever appears.** `System Events` reports no Acepe process among non-background applications.

## Why this is not a build problem

`packages/desktop/src/bun/main.ts` does call `new BrowserWindow({ title, url, frame, rpc })` inside `startAcepeShell`'s `openWindow`. The Bun process runs and does not exit, so the failure is between process start and window creation, and it is **silent** — no thrown error reaches the log.

## Acceptance criteria

1. Find why `openWindow` never runs, or runs without producing a window. Likely candidates: `startAcepeShell` failing inside an Effect whose error is never surfaced, the RPC handler set rejecting at definition time, or the window being created without an activation policy that makes it visible.
2. Whatever the cause, **make the failure loud**. A shell that dies silently between spawn and window is the worst possible failure mode for the QA that follows. Log the cause and exit non-zero.
3. `/tmp/Acepe.app/Contents/MacOS/launcher` opens a visible window showing the Svelte bundle.
4. One RPC round trip from that window is proven with a value assertion, satisfying AC-020's criterion that was never exercised live.

## Notes

This blocks AC-050 entirely. Four tickets (AC-022, AC-042, AC-043, AC-045) deferred their live-app criteria into AC-050, and none of them can be checked until a window exists.

The existing QA wrapper cannot help: `packages/desktop/scripts/acepe-qa.ts` drives the **Tauri** bridge (`com.acepe.app` on port 9223/9227) and has no Electrobun path. Porting it is part of AC-050, not this ticket.
